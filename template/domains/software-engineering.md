# Domain: Software Engineering

Processing rules for code-related sources (articles, papers, documentation, tutorials).

## Extraction Priorities

When processing software engineering content, prioritize:
1. **Patterns over libraries** -- Extract the underlying pattern, not the library-specific API
2. **Trade-offs over recommendations** -- Capture when and why, not just what
3. **Failure modes** -- What goes wrong and under what conditions
4. **Evolution** -- How the approach changed from previous methods and why

## Page Creation Guidance

- Prefer **concept pages** for patterns, principles, and approaches
- Use **entity pages** for specific technologies, frameworks, and tools
- Create **research pages** for landscape surveys and comparisons
- Link implementation details to the concept they illustrate

## Classification Signals

Content likely belongs to this domain if it mentions:
- Programming languages, frameworks, or libraries
- Architecture patterns (microservices, monoliths, event-driven)
- Development practices (TDD, CI/CD, code review)
- System design (scaling, caching, databases)
- API design, protocols, or data formats
